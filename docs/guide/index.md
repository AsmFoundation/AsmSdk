# What is AsmSdk

AsmSdk is the AsmFoundation's project, dependency and build management for x86-64
assembly, on MSBuild and NuGet. Its NuGet package is `AsmFoundation.Sdk`.

An `.asmproj` is to NASM what a `.csproj` is to C#:

- **`dotnet build`** assembles and links it.
- **`ProjectReference` and `PackageReference`** share code between projects, with the same
  version resolution and transitive restore as any .NET project.
- **`dotnet pack`** turns it into a versioned NuGet package that both assembly and .NET
  projects can consume.
- **It sits in the same solution** (`.slnx` or `.sln`) as the C# projects that call it.

```xml
<Project Sdk="AsmFoundation.Sdk">
  <PropertyGroup>
    <AssemblyName>hello</AssemblyName>   <!-- bin/Debug/freestanding/libhello.so -->
  </PropertyGroup>
</Project>
```

## What it builds

| `OutputType` | Output | Notes |
|---|---|---|
| `Library` (default) | `lib<name>.so` | a shared library; position-independent code |
| `StaticLibrary` | `lib<name>.a` | a deterministic archive with a symbol index |
| `Exe` | `<name>` | a static executable entering `_start`, or a PIE entering `main` on glibc |
| `Objects` | `.o` files | objects only, for another project to link |

The output is always **Linux x86-64 ELF**, with NASM syntax and the System V ABI. It builds
the same on Windows, Linux and macOS build machines.

## Nothing to install

- **The toolchain is a NuGet package.** Restore downloads `AsmFoundation.Toolchain` for
  the machine you build on: NASM 3.02, plus LLVM 23.1.5's `ld.lld`, `llvm-ar` and
  `llvm-readobj`. See [The toolchain](../toolchain/index.md).
- **The download is pinned.** Each SDK release names the toolchain version it was tested
  with, and every file behind the toolchain packages is pinned by SHA-256.
- **glibc needs no sysroot.** A project that uses glibc links against a stub generated by
  the SDK, so no Linux system headers or libraries are needed, even on Windows.

## How it works

AsmSdk rides on `Microsoft.NET.Sdk`, the way Microsoft's NoTargets SDK does:

- **The standard .NET parts:** restore, references, versioning, pack and solution builds.
- **What AsmSdk replaces:**
  - compilation, which becomes assemble and link;
  - the steps that only make sense for managed code: no assembly, no apphost, and no
    reference added to a `.csproj` that references an `.asmproj`.
